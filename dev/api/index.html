Module

Surfacelets.Surfacelets — Module
Surfacelets

Three-dimensional nonsubsampled and decimated surfacelet transforms, as transform objects of AbstractMultiscaleTransforms, whose interface this package re-exports.

Quick reference

NameDescription
NSSurfaceletNonsubsampled surfacelet transform: every subband has the size of the volume; streams
SurfaceletDecimated counterpart, subbands at reduced resolution
analyze / synthesize (and ! forms)Run a transform
make_workspaceMasks, buffers and FFT plans for repeated calls on one size
subband_layout / nsubbands / subbandWhat each subband is, and where it is in the coefficients
Surfacelets.make_hourglass / Surfacelets.make_ndfbThe directional stage on its own (public, not exported)

The surfacelet transform is a construction in its own right, not a dimension-raised contourlet transform. Its first directional stage carves the spectrum into three hourglass-shaped regions around the three axes, a partition with no quincunx-lattice description that Lu & Do prove cannot be critically sampled. The nonsubsampled transform builds it from Bernstein mapping kernels and cuts each hourglass into 2^L wedges with directly placed boundaries.

Surfacelet is Lu & Do's decimated surfacelet transform, reproducing their reference toolbox SurfBox to rounding error: a 3/2-resampling Fourier pyramid, SurfBox's hourglass bank, and iterated resampled checkerboard filter banks that refine each hourglass into wedges while decimating critically. About 4 coefficients per voxel, whatever the number of directions (surfacelet_redundancy); not shift-invariant. See the "Theory" page.

The interface

Surfacelets re-exports the interface of AbstractMultiscaleTransforms: analyze, analyze!, synthesize, synthesize!, make_workspace, transform, similar_coefficients, subband_layout, nsubbands, subband, SubbandVector, SubbandLayout, AbstractMultiscaleTransform and AbstractTransformWorkspace. Every function that takes a transform also takes a workspace in its place: analyze(ws, x), analyze!(c, ws, x), synthesize(ws, c), synthesize!(x, ws, c). The methods specific to the two transforms are listed with them below.

Nonsubsampled surfacelet transform

Surfacelets.NSSurfacelet — Type
NSSurfacelet(; scales, direction_levels, bernstein_order = 12, halfband_order = 1,
             transition = 1.0, tight = true)

The nonsubsampled surfacelet transform. Its multiscale stage is Lu and Do's raised-cosine frequency-domain pyramid without its downsampling, a tight frame; see the "Theory" page. Every subband has the size of the data, so the transform is invariant under circular shifts.

  • scales — number of pyramid levels (J in the papers).
  • direction_levels — directional depth per scale (ℓⱼ), length scales, from the coarsest scale to the finest. Scale j produces 3 * 2^(direction_levels[j]) directional subbands.
  • bernstein_order — order N of the Bernstein mapping kernels of the hourglass bank; larger sharpens the boundaries between directional subbands.
  • halfband_order — order m of the 1-D halfband split polynomial.
  • transition — the half-width of the soft step at each wedge boundary, as a fraction of the wedge width: 0 gives hard boundaries, 0.5 lets the two steps of a wedge meet at its center, and 1 (the default) ramps across a whole wedge on either side of each boundary, so no wedge has a flat passband — a plane wave at the center of a wedge keeps about 71 % of its energy there at two directional levels.
  • tight — when true (the default) the directional masks are √W, which makes the whole transform a Parseval frame: ‖Sx‖ = ‖x‖ and the inverse is the adjoint. When false they are the weights themselves and the directional inverse is a bare sum. See Surfacelets.make_hourglass.

Give scales, direction_levels or both. scales alone gives parabolic scaling: one directional level at the two coarsest scales, one more every second scale toward the finest. direction_levels alone gives scales = length(direction_levels); when both are given they must agree.

Run it with analyze and synthesize; repeated calls on one size reuse a NSSurfaceletWorkspace. The transform also streams: analyze(f, t, x) hands the subbands to f one at a time. Real and complex data are accepted; complex data is transformed as two real channels, so analyze(t, x + im * y) == complex.(analyze(t, x), analyze(t, y)) exactly.

julia> using Surfacelets, Random

julia> x = randn(Xoshiro(5), 16, 16, 16);

julia> t = NSSurfacelet(direction_levels = [1, 2], bernstein_order = 6);

julia> c = analyze(t, x);

julia> nsubbands(t, size(x))   # the lowpass, then 6 + 12 directional subbands, coarse to fine
19

julia> maximum(abs, synthesize(t, c) .- x) < 1e-10
true

julia> NSSurfacelet(scales = 4)
NSSurfacelet(scales = 4, direction_levels = [1, 1, 2, 2], bernstein_order = 12, halfband_order = 1, transition = 1.0, tight = true)

Surfacelets.NSSurfaceletWorkspace — Type
NSSurfaceletWorkspace

Masks, buffers and FFT plans of an NSSurfacelet transform for one volume size, element type and array type. Build with make_workspace and pass it as workspace (or in place of the transform) to keep repeated calls out of the allocator — the pattern iterative reconstruction algorithms need.

A workspace holds scratch buffers, so it must not serve two transforms at the same time; it threads internally instead. Adapt.adapt(ArrayType, ws) moves it to a device, rebuilding its buffers and FFT plans there.

AbstractMultiscaleTransforms.make_workspace — Method
make_workspace(t::NSSurfacelet, T::Type{<:Number}, dims; flags = FFTW.MEASURE, tasks = nothing,
               tune = false, prewarm = true, cache_bandpass = true) -> NSSurfaceletWorkspace
make_workspace(t::NSSurfacelet, x::AbstractArray; <same keywords>) -> NSSurfaceletWorkspace

The workspace of t for volumes of size dims (three axes) and element type T (real or complex; an integer type means float(T)). The second form takes size, element type and array type from x: for a device array the workspace is built on the host and moved with Adapt.

Keywords:

  • flags: the FFTW planner flags of the host FFT plans; ignored on a device.
  • tasks: the most tasks a threaded call runs the subbands on, and with them the buffers, one set per task; nothing is one per Julia thread (never more than the threads), 1 a serial workspace. A device runs one.
  • tune: accepted and ignored (there is no device batch tuning).
  • prewarm: run one analysis and synthesis of zeros at construction (on the device, for a device x), so that the first call is compiled and its buffers are touched. Adapt.adapt of a workspace does not run it.
  • cache_bandpass: see below.

Memory: the hourglass response is one real(T) array on the rfft grid, (n₁÷2+1) × n₂ × n₃. The buffers are about 3·tasks + 1 complex arrays of that grid (each the size of two responses) for real data, and 4·tasks + 5 for complex data. With cache_bandpass = true the pyramid's bandpass of each scale is precomputed as well, t.scales more such arrays; it saves recomputing the non-separable factor √(1 - ℓⱼ²) once per hourglass and channel in both directions. Pass false to broadcast it from per-axis vectors instead, so that everything per-scale is vectors and planes.

Throws an ArgumentError when dims is too small for t.scales scales: a scale whose bandpass would be identically zero.

AbstractMultiscaleTransforms.subband_layout — Method
subband_layout(t::NSSurfacelet, dims) -> Vector{@NamedTuple{scale::Int, direction::Int}}

What each subband of t is: the lowpass first, as (scale = 0, direction = 0), then the directional subbands of scale 1 (the coarsest), 2, …, t.scales (the finest), each as (scale = j, direction = k) with k in 1:3·2^t.direction_levels[j]: hourglass 1, 2, 3 in turn, and inside each the wedges in Surfacelets.ndfb_subband_index order. Every subband has size dims.

AbstractMultiscaleTransforms.analyze — Method
analyze(f, t::NSSurfacelet, x; workspace = nothing, threaded = nothing) -> nothing

Streaming analysis: calls f(i, band) once for every subband i of subband_layout(t, size(x)), the directional subbands in increasing i and then the lowpass (i = 1), reusing one buffer between calls. band is valid only until f returns — copy or reduce it there. The analysis runs serially: f is called from the calling task, one subband at a time and in that order, so it need not be thread-safe. threaded does not apply and is ignored. x must be indexed from 1.

This is the form to use at working sizes. At 256³ Float32 with scales = 3 and direction_levels = [2, 2, 3] the full coefficient set is 3.1 GB, while streaming holds the workspace's buffers: without a workspace the call builds a serial one (tasks = 1), a few half-spectrum volumes plus the plans and masks (see make_workspace for the count). A workspace keeps one set of buffers per task, so build the one you stream with as make_workspace(t, x; tasks = 1).

Examples

julia> using Surfacelets, Random

julia> x = randn(Xoshiro(6), 16, 16, 16);

julia> t = NSSurfacelet(direction_levels = [1, 1], bernstein_order = 6);

julia> energy = zeros(nsubbands(t, size(x)));

julia> analyze(t, x) do i, band
           energy[i] = sum(abs2, band)
       end

julia> sum(energy) ≈ sum(abs2, x)
true

synthesize!(f, x, t::NSSurfacelet; workspace = nothing, threaded = nothing) -> x

Streaming synthesis into x: f(i) must return subband i of subband_layout(t, size(x)). Decimated surfacelet transform

Surfacelets.Surfacelet — Type
Surfacelet(; scales, direction_levels, pyramid_ratio = 1.5, checkerboard_order = 12,
           diamond_length = 15, kaiser_beta = 2.5, diamond_power = 4)

Lu and Do's decimated 3-D surfacelet transform, reproducing their reference toolbox SurfBox to rounding error: a 3/2-resampling Fourier pyramid, SurfBox's hourglass bank, and iterated resampled checkerboard filter banks that refine each hourglass into wedges while decimating critically. About 4 coefficients per voxel with the default pyramid_ratio, whatever the number of directions (see surfacelet_redundancy); not shift-invariant. The SurfBox name of each parameter is given in parentheses.

  • scales — number of scales (the length of Lev_array).
  • direction_levels — directional refinement per scale, length scales, from the coarsest scale to the finest (SurfBox's Lev_array lists the scales finest first, so this is reverse(Lev_array)). An integer L gives 2^L wedges in each of the three hourglasses (3 · 2^L subbands), split as evenly as possible between the two transverse axes. A 3 × 3 integer matrix gives SurfBox's level matrix instead: row K holds the number of checkerboard stages along each axis inside hourglass K (the diagonal is ignored), so hourglass K has 2^(sum of row K off the diagonal) wedges.
  • pyramid_ratio — resampling factor of the pyramid (Pyr_mode): 1.5 (default, redundancy ≈ 4), 1 (≈ 6.4) or 2 (≈ 3.4). Every scale size must divide accordingly; see make_workspace.
  • checkerboard_order — order of the checkerboard filters (bo), one of checkerboard_orders() (default 12). Higher is sharper directionally, at no extra cost: the filters are evaluated in closed form in the frequency domain.
  • diamond_length, kaiser_beta, diamond_power — the hourglass diamond kernel: its length (msize, odd), the β of its Kaiser window (beta), and the even power λ it is raised to (lambda).

Give scales, direction_levels or both, as for NSSurfacelet: scales alone gives parabolic scaling, direction_levels alone gives scales = length(direction_levels).

The checkerboard filters are biorthogonal, so the transform is a frame with perfect reconstruction but not a tight one: synthesize is its inverse, not its adjoint. Real and complex data are accepted; complex data is transformed as two real channels, so the transform is exactly real-linear.

julia> using Surfacelets, Random

julia> Surfacelet(direction_levels = [1, 2])
Surfacelet(scales = 2, direction_levels = [1, 2], pyramid_ratio = 1.5, checkerboard_order = 12, diamond_length = 15, kaiser_beta = 2.5, diamond_power = 4)

julia> x = randn(Xoshiro(7), 48, 48, 48);

julia> t = Surfacelet(direction_levels = [1, 2]);

julia> maximum(abs, synthesize(t, analyze(t, x)) .- x) < 1e-10
true

References

  1. Y. M. Lu and M. N. Do, "Multidimensional Directional Filter Banks and Surfacelets", IEEE Transactions on Image Processing, 16(4):918–931, 2007. doi:10.1109/TIP.2007.891785

Surfacelets.SurfaceletWorkspace — Type
SurfaceletWorkspace

Everything a Surfacelet transform needs for one volume size, element type and array type: the pyramid profiles, hourglass masks and checkerboard filter slices, and the spectra, block buffers and FFT plans the transform runs in, so that analyze! and synthesize! allocate only array headers and the threads' tasks: a few kilobytes per call (about 2 KB serial and 11 KB with four tasks for a two-scale 24³ transform). Build with make_workspace and pass it as workspace (or in place of the transform).

A workspace holds its own scratch buffers, so one workspace must not run two transforms at the same time; give each task its own. A transform with the workspace spreads its work over at most the tasks it was built for. Adapt.adapt(ArrayType, ws) moves it to a device, rebuilding the buffers and FFT plans there.

AbstractMultiscaleTransforms.make_workspace — Method
make_workspace(t::Surfacelet, T::Type{<:Number}, dims;
               flags = FFTW.MEASURE, tasks = nothing, tune = false, prewarm = true) -> SurfaceletWorkspace
make_workspace(t::Surfacelet, x::AbstractArray; <same keywords>) -> SurfaceletWorkspace

Precompute everything t needs for volumes of size dims (three axes) and element type T (real or complex; an integer type means float(T)). The second form takes size, element type and array type from x: for a device array the tables are built on the host (the filter slices are evaluated point by point in closed form) and the workspace is moved with Adapt.

Sizes: every axis must fit the pyramid at every scale, J = t.scales of them. From the finest scale (the volume) to the coarsest, the axis length must be even (the hourglass stage) and divisible by the wedge count 2^ℓ of the scale's directional levels along that axis. The pyramid then resamples it, by 3/2 at the finest scale with pyramid_ratio = 1.5 (by 2 with 2, not at all with 1) and by 2 at every coarser one, so the length must be a multiple of 3 (or 2) there; and the resampled length must leave room for the lowpass's support, which rules out short axes. For example, with pyramid_ratio = 1.5 and no directional levels any multiple of 3 · 2^max(1, J - 1) fits. A size that does not fit throws an ArgumentError naming the axis, the scale and the nearest length that does.

Keywords:

  • flags: the FFTW planner flags of the host FFT plans; pass FFTW.ESTIMATE for a workspace used once. Ignored on a device.
  • tasks: the most tasks a transform with the workspace uses: the blocks of a scale are split among that many tasks, each with a buffer of one block, and the full-volume FFTs run on that many FFTW threads (on one in a serial call). nothing is one per Julia thread, 1 a serial workspace. A device runs one.
  • tune: accepted and ignored (there is no device batch tuning).
  • prewarm: run one analysis and synthesis of zeros at construction (on the device, for a device x), so that the first call is compiled and its buffers are touched. Adapt.adapt of a workspace does not run it.

AbstractMultiscaleTransforms.subband_layout — Method
subband_layout(t::Surfacelet, dims) -> Vector{@NamedTuple{scale::Int, hourglass::Int, wedge::Int}}

What each subband of t is: the lowpass first, as (scale = 0, hourglass = 0, wedge = 0), then for scale 1 (the coarsest), 2, …, t.scales (the finest) the wedges of hourglass 1, 2, 3 in turn, (scale = j, hourglass = K, wedge = w) with the wedges in SurfBox's order. Directional filter bank

The directional stage of the nonsubsampled transform on its own, without the pyramid. These names are public but not exported: call them as Surfacelets.make_ndfb, or import them with using Surfacelets: make_ndfb, ndfb_decompose.

Surfacelets.HourglassFB — Type
HourglassFB{T}

Precomputed 3-D nonsubsampled hourglass filter bank for one volume size and real precision T (its eltype). Build with make_hourglass. A bank's buffers serve one call at a time: tasks that run decompositions or reconstructions concurrently need a bank each.

Holds the two mapping-kernel frequency responses (m1 on the 3-D rfft grid, m2 on the 2-D (ω₂, ω₃) grid) rather than the three subband masks, which are derived pointwise on the fly — a third of the memory, and the polynomial evaluation is negligible next to the transforms.

Surfacelets.make_hourglass — Function
make_hourglass([T = Float64,] dims; bernstein_order = 12, halfband_order = 1, tight = true,
               threaded = nothing, flags = FFTW.MEASURE) -> HourglassFB
make_hourglass([T = Float64,] n1, n2, n3; kwargs...) -> HourglassFB

Build the 3-D hourglass filter bank for volumes of size dims (or (n1, n2, n3)) and precision T.

bernstein_order is the Bernstein order N of the mapping kernels: larger N sharpens the transition between hourglass subbands (Lu & Do use N = 12, which in their FIR realization corresponds to filters of support up to 61³ — here it costs nothing but a slightly longer design step). halfband_order is the order m of the 1-D halfband split polynomial; larger m flattens the response near the passband centers. Neither affects perfect reconstruction, which is exact for any choice.

A bank's buffers serve one call at a time: tasks that run decompositions or reconstructions concurrently need a bank each.

tight selects how the three weights become filters. With tight = true (the default) the masks are √W_i, so the bank is a Parseval frame — analysis preserves energy, Σ_i ‖s_i‖² = ‖x‖² — and synthesis applies the same masks, costing one forward transform per subband plus one inverse. With tight = false the masks are the weights themselves, reconstruction is a bare sum with no transforms, and the frame-bound ratio is 3. Perfect reconstruction is exact either way.

A complex element type is accepted and produces a plan of the corresponding real precision; complex volumes are filtered as two real passes, keeping T(x + i·y) == T(x) + i·T(y) exact.

Surfacelets.hourglass_mask — Function
hourglass_mask(fb::HourglassFB, i::Integer) -> Array{T,3}

The frequency-domain analysis mask of hourglass subband i (1, 2 or 3) on the rfft grid. Materializing it is only useful for inspection and tests — the transform derives mask values on the fly.

The three masks sum to 1 at every frequency when fb.tight is false, and their squares sum to 1 when it is true. See hourglass_weight for the underlying partition of unity in either case.

The frequency-domain weight W_i of hourglass subband i on the rfft grid, before the tight normalization. The three weights are a partition of unity — Σ_i W_i = 1 at every frequency — for any bernstein_order/halfband_order.

Surfacelets.hourglass_decompose — Function
hourglass_decompose(volume, fb::HourglassFB) -> (s₁, s₂, s₃)

Split volume into the three hourglass subbands. Every subband keeps the full size of the input — the bank is nonsubsampled, so the decomposition is exactly equivariant under circular shifts and the redundancy is 3 (N in N-D, which Lu & Do show is unavoidable: hourglass partitioning cannot be critically sampled above 2-D). It runs in fb's buffers, so fb serves one call at a time.

Examples

julia> using Surfacelets, Random

julia> using Surfacelets: make_hourglass, hourglass_decompose, hourglass_reconstruct

julia> x = randn(Xoshiro(2), 16, 16, 16);

julia> fb = make_hourglass(Float64, size(x); bernstein_order = 6);

julia> s = hourglass_decompose(x, fb);

julia> maximum(abs, hourglass_reconstruct(s, fb) .- x) < 1e-10
true

Surfacelets.hourglass_reconstruct — Function
hourglass_reconstruct(subbands, fb::HourglassFB) -> volume

Invert hourglass_decompose. Perfect reconstruction holds exactly for any bernstein_order/halfband_order — it is structural, not an approximation that degrades with filter sharpness.

When fb.tight is false the synthesis filters are all 1 and this is a plain sum, with no transforms. When it is true the same √W masks are applied on the way back, so each subband costs a forward transform and the sum is completed by one inverse.

NDFB{T}

3-D nonsubsampled directional filter bank of real precision T (its eltype): HourglassFB followed by a wedge refinement of each hourglass. Build with make_ndfb. A bank's buffers serve one call at a time: tasks that run decompositions or reconstructions concurrently need a bank each.

Surfacelets.make_ndfb — Function
make_ndfb([T = Float64,] dims; levels = 2, bernstein_order = 12, halfband_order = 1, tight = true,
          transition = 1.0, threaded = nothing, flags = FFTW.MEASURE) -> NDFB
make_ndfb([T = Float64,] n1, n2, n3; kwargs...) -> NDFB

Build a 3-D NDFB producing 3 * 2^levels directional subbands, each the full size of the input. A bank's buffers serve one call at a time: tasks that run decompositions or reconstructions concurrently need a bank each.

levels is the total refinement depth L; it is split as evenly as possible between the two transverse planes of each hourglass (l_a = ceil(L/2), l_b = floor(L/2)), matching the balanced expansion rule of the paper. levels = 0 leaves the plain three-subband hourglass bank.

bernstein_order (Bernstein order N), halfband_order (halfband polynomial order m) and tight are forwarded to make_hourglass; with tight = true (the default) the whole bank is a Parseval frame, since the wedge weights are themselves a partition of unity. transition is the half-width of the soft step at each wedge boundary, as a fraction of the wedge width: 0 gives hard boundaries, 0.5 lets the two steps of a wedge meet at its center, and 1 (the default) ramps across a whole wedge on either side of each boundary, so no wedge has a flat passband — a plane wave at the center of a wedge keeps about 71 % of its energy there at levels = 2.

Surfacelets.ndfb_sharing — Function
ndfb_sharing(fb::HourglassFB; levels = 2, halfband_order = fb.halfband_order, transition = 1.0) -> NDFB

Build a directional bank on top of an existing hourglass bank instead of planning a new one. The hourglass stage depends only on the volume size, so a multiscale transform can plan it once and vary only the wedge refinement per scale — the wedge masks are matrices, so an extra scale costs kilobytes. levels, halfband_order and transition are those of make_ndfb.

The returned bank runs in fb's buffers, as does every other bank built on fb: at most one of them may be in use at a time.

Surfacelets.ndfb_subband_index — Function
ndfb_subband_index(fb::NDFB, hourglass, p, q) -> Int

Linear index of the subband refining hourglass (1-3) at wedge p of its first transverse plane and wedge q of its second. Subbands are ordered hourglass first, then p, then q. Wedges are numbered from 1; the two planes have na and nb wedges with na * nb = 2^levels, and an index outside 1:na, 1:nb or 1:3 throws an ArgumentError.

Surfacelets.ndfb_decompose — Function

All 3 * 2^levels directional subbands, each the size of volume. It runs in fb's buffers, so fb serves one call at a time.

Memory warning: at 256³ Float32 a single subband is 64 MB, so levels = 3 (24 subbands) materializes 1.5 GB. Use the callback form below to process subbands one at a time instead.

ndfb_decompose(f, volume, fb::NDFB)

Streaming decomposition: calls f(idx, subband) once per directional subband, reusing a single scratch buffer between calls. subband is only valid until f returns — copy or reduce it there. Returns nothing.

This is the form to use on real volumes: it holds one subband at a time instead of 3 * 2^levels of them.

Hourglass filter design

The Bernstein mapping kernels the hourglass bank is built from, for designing other kernels. Public but not exported, like the names in the section above.

Surfacelets.bernstein_table — Function
bernstein_table(N::Integer, omega::AbstractVector{T}) -> Matrix{T}

Evaluate the order-N Bernstein basis at the frequencies omega, after the change of variables x = (1 - cos ω) / 2. Returns an (N+1) × length(omega) matrix whose [j+1, k] entry is binomial(N, j) x_k^j (1 - x_k)^(N-j).

The columns sum to 1, so any convex combination of rows stays in [-1, 1] when the coefficients do — this is what bounds the mapped filter responses.

Surfacelets.mapping_coefficients — Function
mapping_coefficients(N::Integer, d::Integer, group::NTuple{G, Integer}) -> Array{Int,d}

Coefficient tensor of the Bernstein mapping kernel whose passband is

S = {ω : max_{i ∈ group} |ω_i| ≥ max_{i ∉ group} |ω_i|},

the "simplest passband support" of Lu & Do (2008), Proposition 1 — the optimal choice for splitting a node of the hourglass cascade tree.

Entries are +1 inside S, -1 outside, and 0 on the boundary, evaluated at the Bernstein sample points j / N. Only the ordering of the indices matters, which is why the sample points never have to be converted back to frequencies.

source
Surfacelets.mapping_response — Function
mapping_response(coeffs, tables) -> Array

Evaluate a multivariate Bernstein mapping kernel on a DFT grid. coeffs is the (N+1)^d coefficient tensor from mapping_coefficients and tables is a d-tuple of per-axis Bernstein tables from bernstein_table, one per grid axis. The result is the real, zero-phase frequency response M(ω) on the product grid, with |M| ≤ 1 wherever the coefficients are in [-1, 1]. coeffs and the tables must be indexed from 1: entry [j+1, k] of a table is Bernstein term j.

Evaluated by successive axis contractions rather than by summing (N+1)^d separable outer products, so the cost is O(N · ∏ nᵢ) and not O(N^d · ∏ nᵢ).

Surfacelets.halfband_split — Function
halfband_split(x, m::Integer) -> f₀

The maximally flat 1-D polynomial used to turn a mapping kernel into a two-channel split:

f₀(x) = ((1+x)/2)^(m+1) · Σ_{k=0}^{m} binomial(m+k, k) · ((1-x)/2)^k,
f₁(x) = 1 - f₀(x).

f₀(1) = 1, f₀(-1) = 0, and f₀(x) + f₀(-x) = 1, so f₁(x) = f₀(-x) — the two channels are mirror images and their sum is exactly 1. With synthesis polynomials g₀ = g₁ = 1 the Bézout/perfect-reconstruction condition f₀g₀ + f₁g₁ = 1 therefore holds identically, and reconstruction is a plain sum of the subbands.

m controls the transition sharpness: m = 0 gives (1+x)/2, larger m is flatter at x = ±1 at the cost of a steeper polynomial.
